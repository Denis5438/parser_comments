# Технический план разработки бота для автоматизации розыгрышей

**Стек:** Node.js (LTS 20+) / TypeScript  
**Платформы:** YouTube, ВКонтакте, Дзен, Instagram  
**Архитектура:** ⚡ **Zero-Browser & Zero-Setup**
* **Серверные ресурсы:** Без запуска браузеров (Chromium, Playwright, Puppeteer). Потребление RAM всего **60–90 МБ**, идеальная стабильность на слабом VPS (512 МБ – 1 ГБ).
* **Для заказчика:** «Под ключ» — заказчику **не нужно** регистрироваться в кабинетах разработчиков Meta/Facebook, передавать токены или вводить свои пароли. Бот работает автономно по ссылке на пост.

---

## 1. Сценарий работы заказчика

1. Заказчик отправляет боту в Telegram ссылку на публикацию (YouTube, VK, Дзен, Instagram).
2. Бот автоматически определяет платформу и проверяет доступность ссылки.
3. Бот предлагает выбрать правила отсева (кнопками в чате):
   * *«Оставлять только 1-й комментарий»* (по умолчанию) — повторные комментарии отсеиваются в отдельный список дублей.
   * *«Дисквалификация»* — участники с $\ge 2$ комментариями исключаются полностью.
   * *«Учитывать ответы»* — собирать только комментарии первого уровня или все ветки.
4. Запускается быстрый сетевой сбор данных с отображением статуса в чате.
5. Бот возвращает:
   * **Сводку сообщением:** общее количество комментариев, число честных участников, число исключенных повторов.
   * **Excel-файл (.xlsx)** с присвоенными порядковыми номерами (1, 2, 3... $N$) и кликабельными ссылками на профили.
   * **Кнопку «Выбрать победителя»:** встроенный генератор случайного номера для прозрачного подведения итогов прямо в боте.

## 2. Легковесный сбор данных (Zero-Browser / Pure HTTP)

Все интеграции работают строго по протоколу HTTPS через легковесные REST/JSON запросы без прожорливых браузеров:

| Платформа | Метод сбора | Нагрузка на RAM | Как устроен сбор | Что нужно от заказчика |
| :--- | :--- | :---: | :--- | :---: |
| **Instagram** | **Автономный шлюз бота** (Mobile/Web API через чистый HTTPS) | ~15–20 МБ | Бот сам запрашивает данные поста через свой встроенный технический контекст. **Без браузера и без токенов от заказчика.** | **Ничего!** Только ссылка на пост. |
| **YouTube** | YouTube Data API v3 (`googleapis` / `fetch`) | ~5–10 МБ | Официальный Google REST API (`commentThreads.list`). Быстрая постраничная выгрузка. | Ключ API (создается 1 раз). |
| **ВКонтакте** | VK API (`vk-io` / `fetch`) | ~5–10 МБ | Официальный REST API (`wall.getComments` / `video.getComments`). Сбор по 100 комментариев за шаг. | Сервисный токен (1 минута). |
| **Дзен** | Внутреннее REST API комментариев Дзена (`undici` / `fetch`) | ~10–15 МБ | Прямые GET-запросы к JSON-эндпоинтам комментариев веб-версии Дзена с парсингом чистого JSON. | **Ничего!** Ссылки открытые. |

## 3. Алгоритм дедупликации и нумерации

1. **Нормализация данных:**  
   Каждый собранный комментарий приводится к стандартной структуре:
   ```typescript
   interface RawComment {
     userId: string;        // Уникальный ID профиля (защита от смены ника)
     username: string;      // Никнейм / имя
     profileUrl: string;    // Прямая ссылка на страницу участника
     commentText: string;   // Текст комментария
     createdAt: Date;       // Точное время отправки
   }
   ```
2. **Хронологическая сортировка:**  
   Все комментарии сортируются строго по времени публикации (`createdAt ASC`).
3. **Фильтрация повторов:**  
   * Сверка участников ведется по уникальному `userId`.
   * **Режим «Первый засчитан»:** самый ранний комментарий автора попадает в список участников, последующие помечаются как спам/дубли.
   * **Режим «Дисквалификация»:** если у автора $\ge 2$ комментариев, он полностью удаляется из розыгрыша.
4. **Присвоение номеров:**  
   Участникам строго по хронологии выдаются номера: $1, 2, 3 \dots N$.

## 4. Оформление отчета Excel (`exceljs`)

Формируется стилизованный `.xlsx` файл (в режиме стриминга, не нагружающем память):
* **Лист 1 («Участники розыгрыша»):**  
  `№ п/п` | `Никнейм` | `Ссылка на профиль` (гиперссылка) | `Текст комментария` | `Дата/время`
* **Лист 2 («Исключенные дубликаты»):**  
  Список всех повторов с указанием количества попыток и текстов, чтобы заказчик мог легко разрешить любые спорные ситуации с подписчиками.

## 5. Технический стек

* **Runtime:** Node.js 20+ LTS
* **Язык:** TypeScript
* **Telegram Framework:** `grammY` (минимальное потребление CPU и памяти)
* **Сетевой уровень:** `undici` / `fetch` / `axios`
* **Генерация таблиц:** `exceljs` (стриминговая запись)
* **Интеграции:** `googleapis` (YouTube), `vk-io` (VK), легковесные сетевые парсеры (Instagram, Дзен).
